# github-actions-matrix (2026-11-02)

A matrix strategy lets one job definition fan out into many parallel runs, one for each combination of variables you define. It is the standard way to test across operating systems, language versions, or configurations without copying YAML.

```yaml
strategy:
  fail-fast: false
  max-parallel: 4
  matrix:
    os: [ubuntu-latest, windows-latest]
    node: [18, 20, 22]
    include:
      - os: ubuntu-latest
        node: 24
        experimental: true
    exclude:
      - os: windows-latest
        node: 18
```

## Tips

- Reference values with `${{ matrix.node }}`.
- Set `fail-fast: false` so one failing leg doesn't cancel the others and hide other problems.
- Use `include` to add one-off combinations and `exclude` to prune unsupported ones.
- Use `max-parallel` to limit concurrency and protect shared resources or rate limits.
- Keep names readable: matrix legs appear as separate checks, which matters for branch protection rules.
- A matrix can generate at most 256 jobs per workflow run.

Build matrices dynamically from JSON with `fromJSON` when the list of targets changes often.
