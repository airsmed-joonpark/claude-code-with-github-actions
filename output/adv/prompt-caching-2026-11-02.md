# prompt-caching (2026-11-02)

Prompt caching lets you reuse the processed prefix of a prompt across API requests, cutting both latency and cost for repetitive workloads.

## How it works

Mark a stable prefix, such as a system prompt, tool definitions, or a large document, with a cache breakpoint. Later requests that begin with the identical prefix read from the cache instead of reprocessing it. Cache reads are billed at a fraction of normal input token prices, while cache writes carry a small premium.

## Practical tips

- Put static content first and dynamic content (user input, timestamps) last.
- Any change in the prefix invalidates the cache from that point onward.
- Caches expire after a short time-to-live, so steady traffic keeps them warm.
- Very short prompts fall below the minimum cacheable length.
- Check the usage fields in responses to confirm cache hits.

## Good fits

Agents with long tool lists, chat with large context, and document question answering benefit most.
