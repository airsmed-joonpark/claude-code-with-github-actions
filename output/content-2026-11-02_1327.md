## 1. Upload build and test output
Use `actions/upload-artifact` to keep files such as build output or coverage reports. Paths can be files, directories or wildcards, and `!` excludes files. If you give no name, it defaults to `artifact`.
```yaml
- uses: actions/upload-artifact@v4
  with:
    name: dist-without-markdown
    path: |
      dist
      !dist/**/*.md
```
Source: [Store and share data with workflow artifacts](https://docs.github.com/en/actions/tutorials/store-and-share-data)

## 2. Set a custom retention period
Use `retention-days` per artifact. It cannot exceed the limit set by the repository, organization or enterprise.
```yaml
with:
  name: my-artifact
  path: my_file.txt
  retention-days: 5
```

## 3. Download artifacts in a later step or job
`actions/download-artifact` fetches an artifact by `name`. With no name, it downloads all artifacts from the run, one directory per artifact. To pull artifacts from another run or repository, you must supply a token and run identifier ([details](https://github.com/actions/download-artifact)).

## 4. Pass data between jobs
Upload in one job, then use `needs:` so a later job waits and downloads it. Artifacts are immutable in v4, so a modified file must be uploaded under a new name (the docs use `homework_pre`, then `homework_final`).

## 5. Validate with the digest
`upload-artifact` outputs a SHA256 `digest`. `download-artifact` recomputes it and shows a warning in the UI and logs on mismatch.
